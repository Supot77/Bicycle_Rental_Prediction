# Bicycle Lab: เว็บกลางติดตามงานกลุ่ม

เว็บกลางแบบไม่เป็นทางการสำหรับดูไกด์แบ่งงาน M1–M5 เปิด Colab/GitHub และจดสถานะ โน้ต หรือลิงก์งานร่วมกัน ลำดับกับบทบาทปรับได้ ไม่ต้องทำทุกขั้นตามเป๊ะ ๆ งานพัฒนาและฝึกโมเดลทำใน Colab ส่วนแอปทำนายจริงเผยแพร่บน Streamlit Community Cloud ตามโจทย์

## วิธีใช้สำหรับสมาชิก

1. เปิดลิงก์เว็บแอปที่เจ้าของส่งให้กลุ่ม แล้วลงชื่อเข้า Google
2. เลือกมุมมอง M1–M5 ตามบทบาทที่คุยกัน หรือดูทุกคนในทีม
3. ดูไอเดียงานของทีมแล้วเลือกส่วนที่อยากเริ่มก่อน กดงานเพื่ออ่านแนวทาง สิ่งที่อาจส่งต่อ และเพื่อนที่ชวนช่วยดูได้
4. เปิด Colab จากงานนั้น ทำส่วนที่กลุ่มเลือกแล้วบันทึกสำเนาใน Drive หรือ GitHub
5. ถ้าต้องการ ให้เลือกสถานะ ใส่โน้ตหรือลิงก์ แล้วกดบันทึกให้เพื่อนดู
6. กดโหลดสถานะล่าสุดเมื่ออยากเห็นงานของเพื่อนทันที หน้าเว็บโหลดอัตโนมัติประมาณทุก 90 วินาทีเมื่อไม่ได้กรอกข้อมูลหรือเปิดรายละเอียดค้าง

มีสถานะ ยังไม่เริ่ม / กำลังทำ / รอตรวจ / เสร็จแล้ว / ติดปัญหา เป็นตัวช่วยสื่อสารในกลุ่ม จะเริ่มหรือปิดงานไหนก่อนก็ได้ โน้ตกับหลักฐานเป็นตัวเลือก ความคืบหน้าแสดงสิ่งที่สมาชิกบันทึก ไม่ได้ตรวจไฟล์ให้อัตโนมัติ

ถ้าเพื่อนแก้งานเดียวกันก่อนบันทึก เว็บจะแจ้งข้อมูลล่าสุดและเก็บข้อความที่กำลังกรอกไว้ ให้เปรียบเทียบแล้วเลือกใช้ข้อมูลล่าสุดก่อนส่งใหม่ ไม่เขียนทับกันเงียบ ๆ

## การเข้าถึงและขอบเขตข้อมูล

เวอร์ชันเริ่มต้นเผยแพร่ให้ผู้ที่มีบัญชี Google และได้รับลิงก์เข้าถึงได้ ผู้เข้าถึงสามารถอ่านและแก้สถานะร่วมกันได้ ยังไม่มี allowlist เฉพาะอีเมลสมาชิกห้าคน การเลือกบทบาทเป็นเพียงตัวกรองและข้อความระบุผู้บันทึก ไม่ใช่การยืนยันตัวบุคคลหรือระบบสิทธิ์

ส่งลิงก์เว็บแอปที่แก้สถานะได้ให้กลุ่มเป็นการส่วนตัว ไม่วางลิงก์นั้นใน repository สาธารณะ เว็บไม่รับ dataset, student IDs, credentials หรือไฟล์โมเดล ช่องหลักฐานเก็บเพียง HTTPS URL ไม่เปลี่ยนสิทธิ์ของไฟล์ปลายทางให้เอง

สถานะ โน้ต และลิงก์เก็บร่วมกันใน Script Properties ของโปรเจกต์ หนึ่ง property ต่อหนึ่งงาน ไม่ผูกกับเบราว์เซอร์และไม่เขียนกลับ CSV บน GitHub เว็บนี้ไม่เก็บหรืออัปโหลดไฟล์ GitHub API อัปโหลดอัตโนมัติต้องเพิ่มสิทธิ์/credential ที่ไม่ควรฝังในเว็บที่ใช้ร่วมกัน จึงให้สมาชิกบันทึก notebook ผ่าน Colab หรืออัปโหลดไฟล์ผ่าน GitHub เอง แล้วเอาลิงก์มาใส่ในเว็บ

## ไฟล์และการอัปเดตสำหรับผู้ดูแล

| ไฟล์ | หน้าที่ |
| --- | --- |
| Code.gs | doGet, อ่าน/บันทึกสถานะร่วมกัน พร้อม lock และ revision check |
| Index.html | หน้าเว็บ responsive และ google.script.run |
| project-data.json | บทบาท ช่วงงาน คำอธิบาย และ resource links |
| appsscript.json | ตัวอย่าง manifest V8/เขตเวลา |
| tests/backend.test.cjs | ทดสอบ backend โดยจำลองบริการ Google ไม่แตะสถานะจริง |

Code.gs ใช้ planned tasks จาก evidence/task_board.csv รวมกับคำอธิบายใน project-data.json ตัว build ไม่ส่ง status, note หรือหลักฐานจริงของทีมขึ้น source code และไม่ลบ Script Properties

หลังแก้แผน ผู้ดูแลรัน `python scripts/build_apps_script.py` แล้วตรวจ diff ก่อนคัดลอก Code.gs ไปไฟล์ .gs ในโปรเจกต์ และ Index.html ไปไฟล์ HTML ชื่อ Index ผ่านตัวแก้ไข Apps Script ไฟล์ .gs เดิมชื่อไทยได้ ส่วน Index ต้องตรงกับ doGet

เผยแพร่การแก้ไขผ่าน Manage deployments → Edit → New version เพื่อรักษาลิงก์เดิม การกด Save โค้ดอย่างเดียวยังไม่เปลี่ยน /exec ของ deployment ที่ตรึงรุ่นไว้ อย่าเปลี่ยน STORE_PREFIX_ หรือ task IDs ที่ใช้งานแล้วโดยไม่วางแผนย้ายข้อมูล

ไม่มีการเรียก Drive API หรืออ่านบัญชี Google ของสมาชิก โค้ดใช้ HtmlService, PropertiesService และ LockService สำหรับหน้าเว็บนี้เท่านั้น

## การตรวจที่ทำ

`node --test apps-script/tests/backend.test.cjs` ตรวจสถานะเริ่มต้น การอ่านร่วมกัน การป้องกัน stale writes การอัปเดตข้ามลำดับงาน input validation ขนาดข้อความ และข้อมูลเก็บที่เสียหาย เป็นการตรวจของผู้ดูแล ไม่ใช่ขั้นตอนที่สมาชิกต้องติดตั้ง Node เพื่อทำโครงงาน

การทดสอบบันทึกผ่าน UI ใช้ preview ที่เก็บข้อมูลจำลองแยกจากเว็บทีมจริง เว็บจริงตรวจการเปิดและโหลดข้อมูลเริ่มต้นจาก Apps Script ไม่เติมความคืบหน้าทดลองแทนสมาชิก
