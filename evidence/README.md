# หลักฐานที่สมาชิกบันทึกระหว่างทำ

task_board.csv มีรายการงานเสนอสำหรับ M1–M5 โดยทุกงานยังไม่เริ่ม รหัสเหล่านี้ยังไม่ใช่การมอบหมายชื่อจริง ส่วน CSV หลักฐานอื่นมีเฉพาะหัวตาราง ยังไม่มีผลงาน ผลทดลอง หรือผลทดสอบจริง ใช้ UTF-8 อ่าน/แก้ผ่าน Python ใน Colab หรือตัวแก้ไฟล์ข้อความใน Files ได้ หากข้อความมี comma ให้ใส่ในเครื่องหมายคำพูดตามรูปแบบ CSV

| ไฟล์ | เติมเมื่อใด |
| --- | --- |
| `task_board.csv` | รับงาน วางสิ่งส่งต่อ อัปเดตสถานะและผู้ตรวจ |
| `data_dictionary.csv` | รับข้อมูลและยืนยันความหมาย/หน่วย/เวลาที่รู้ค่า |
| `experiments.csv` | รันการทดลองจริงแต่ละรอบ ระบุชุดที่ประเมิน |
| `test_log.csv` | ทดสอบจริง พร้อม expected/actual และการตรวจซ้ำ |
| `monitoring.csv` | ดู log หรือบันทึกจริง ไม่สร้างเหตุการณ์สมมติ |
| `contributions.csv` | ทำงานแล้ว มีหลักฐานที่เปิดตรวจได้ |
| `prompts.csv` | ใช้ AI จริง บันทึกการตรวจและการแก้ |
| `decisions.md` | ตกลงวิธีทำหรือรับคำยืนยัน พร้อมเหตุผล |
| `handoff_template.md` | คัดลอกเพื่อส่ง schema/split/recipe/artifact ให้ผู้รับลองและตรวจรับจริง |
| `split_manifest_template.md` | บันทึกกฎ ช่วง และจำนวนแถว เพื่อให้ทุกโมเดลใช้ split เดียวกัน |
| `model_card_template.md` | ระบุที่มา รุ่น schema ผลประเมิน และวิธีโหลด artifact ตัวที่ส่งให้แอป |

ตัวอย่างคอลัมน์เป็นแนวทาง กลุ่มปรับได้ ไม่ต้องกรอกชื่อคนอื่นแทนกันและไม่ย้อนหลังเดาผลงาน

บันทึก `evaluation_set` เป็น train/validation/test ให้ชัด ใช้ `not_measured` เมื่อยังไม่ได้วัด แต่อย่านำแถวที่ยังไม่วัดไปอ้างเป็นผลสำเร็จ อย่าเติม 0 แทนค่าว่างของคะแนน

เก็บ logs ที่มีข้อมูลจำกัดสิทธิ์ไว้ใน `evidence/private/` ซึ่ง Git ไม่ติดตาม แล้วสรุปหลักฐานที่เผยแพร่ได้แยกต่างหาก หลีกเลี่ยงการใส่ข้อมูลอ่อนไหวลงช่อง input ของ test log
