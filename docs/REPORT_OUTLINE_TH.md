# โครงร่างรายงานสำหรับสมาชิกเติมจากงานจริง

เอกสารนี้ให้คำถามสำหรับเขียน ไม่ใช่รายงานสำเร็จรูป

## 1. ปัญหาและข้อมูล (CO1)

ใครใช้ระบบ เพื่อประโยชน์อะไร หนึ่งแถวหมายถึงอะไร target หน่วยและ input คืออะไร แหล่งข้อมูลและสิทธิ์เป็นอย่างไร พบข้อจำกัดอะไรจากการสำรวจ

## 2. ออกแบบและ preprocessing (CO2)

ข้อมูลไหลผ่านขั้นตอนใด เลือก/ตัด feature เพราะอะไร จัดการ missing/category/scaling อย่างไร แบ่ง train/validation/test เพราะอะไร และป้องกัน leakage อย่างไร

## 3. พัฒนาและเปรียบเทียบ (CO2)

baseline และอัลกอริทึมที่ทดลองคืออะไร settings ใดสำคัญ ใช้ split เดียวกันอย่างไร ตาราง MAE/RMSE/R² บอกอะไร พบ error ในกรณีใด

## 4. โมเดลสุดท้ายและข้อจำกัด (CO2)

เลือกจาก validation และ practical constraints อย่างไร ผล test ของ artifact สุดท้ายเป็นอย่างไร จำกัดบริบทใช้งานแค่ไหน และมีแนวปรับปรุงอะไรที่เชื่อมกับผลจริง

## 5. ระบบและหลักฐาน (CO3)

แอปโหลด pipeline อย่างไร ตรวจ input อะไร ผลเทียบ notebook เป็นอย่างไร deploy ที่ไหน ทดสอบอะไร พบ monitoring observations ใดและจะทบทวนเมื่อใด

## 6. บทสรุปและอ้างอิง

ตอบปัญหาที่ตั้งไว้ได้ระดับใด หลักฐานรองรับคืออะไร และมีงานใดเป็นข้อเสนออนาคต อ้างอิง dataset และเอกสารที่ใช้จริง

## ภาคผนวก

Contribution พร้อมรหัสและหลักฐานสมาชิกทั้งห้า prompts อย่างน้อยห้าช่วงพร้อมวิธีตรวจ และ test evidence เพิ่มเติม

ตรวจรายงาน PDF ว่าอยู่ประมาณ 8–12 หน้าไม่รวมปก อ้างอิง และภาคผนวก ตรวจว่าไม่เขียนแผนที่ยังไม่ได้ทำเป็นผลที่ทำแล้ว และไม่ใช้ข้อมูลตัวอย่างอธิบายเป็นคะแนนจริง
