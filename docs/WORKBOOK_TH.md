# แผนลงมือทีละช่วง

ใช้ควบคู่กับไกด์ฉบับเต็ม งานแต่ละช่วงมีสิ่งส่งต่อที่ตรวจได้ สมาชิกเป็นผู้ทำการวิเคราะห์และเขียนโค้ดส่วนแบบฝึกเอง

## 0. เริ่มงานร่วมกัน — ทำได้ทันที

เปิดลิงก์ Colab ใน START_HERE บันทึกสำเนาใน Drive ทำ notebook 00 จัดตารางงานและวิธีตรวจข้ามคน คุยว่ารอคำยืนยันอะไรจากอาจารย์ สมาชิกทำงานพัฒนาบน Colab เท่านั้น

สิ่งส่งต่อ: ทุกคนเปิด notebook ได้ มีงานแรกของตน และบอกได้ว่างานนี้ต้องส่งอะไร ตรวจโดยให้เพื่อนเปิดงานตามคำแนะนำหนึ่งรอบ

## 1. รับและเข้าใจข้อมูล — notebook 01

ยืนยันหนึ่งแถว target หน่วย เวลา แหล่งที่มา และสิทธิ์ข้อมูล เติม data_dictionary กับ config แล้วตรวจหัวตาราง

สิ่งส่งต่อ: พจนานุกรมและขอบเขตที่อธิบายได้ ผู้ตรวจถามได้ว่า “ข้อมูลเข้าตัวนี้รู้ก่อนทำนายจริงหรือไม่” ถ้าตอบไม่ได้ให้รอการยืนยัน ไม่ข้ามไปฝึก

## 2. ตรวจและสำรวจ — notebook 02

ตรวจคุณภาพข้อมูล กำหนดช่วงประเมินเพื่อกัน test ก่อนตัดสินใจจากรูปแบบข้อมูล ใช้ train สำรวจรูปแบบและเขียนความหมายของกราฟด้วยตนเอง

สิ่งส่งต่อ: รายการปัญหา กราฟพร้อมข้อสังเกต และคำถามที่ยังไม่รู้ ตรวจว่าไม่มีการลบค่าสูงหรือแทนค่าศูนย์แบบไม่มีเหตุผล

## 3. ออกแบบ split และ preprocessing — notebook 03

เขียนบริบทการทำนายก่อนเลือก split ถ้าทำนายอนาคตต้องรักษาลำดับเวลา กำหนดวิธีจัดการ entities/แถวซ้ำตามโจทย์จริง แล้วเขียน preprocessing ที่ fit เฉพาะ train

สิ่งส่งต่อ: ขอบเขตแต่ละชุด แผนภาพและโค้ด preprocessing ผู้ตรวจตรวจเวลา แถวซ้ำ และ feature เฉลย ยังไม่กำหนดสัดส่วน split หรือวิธีเติมค่าตายตัวให้สมาชิก

## 4. ทดลองและประเมิน — notebook 04

เขียน baseline และอย่างน้อย 2 อัลกอริทึมที่กลุ่มเลือก ใช้ validation เลือกค่าตั้งและแนวทาง บันทึก MAE/RMSE/R² พร้อมข้อผิดพลาดและ practical constraints

สิ่งส่งต่อ: experiment log ผลเปรียบเทียบและเหตุผลเลือก หลังเลือกแล้วจึงประเมิน test และบันทึก artifact ตัวที่จะใช้ในแอป ผู้ตรวจทำซ้ำและตรวจว่า baseline ไม่ถูกนับแทนอัลกอริทึมที่สอง

## 5. เชื่อมระบบ — notebook 05 และ app.py

โหลด pipeline ใหม่ เทียบผลเดิม เขียนช่องกรอกและ validation ด้วย schema จริง ทดสอบ input เดียวกันกับ notebook และกำหนดวิธีจัดรูปแบบผล

สิ่งส่งต่อ: app.py ที่ทำนายจริงพร้อม artifact และ test log ผู้ตรวจต้องโหลด artifact และรัน AppTest ใน Colab session ใหม่ได้ จากนั้นดูหน้าจอจริงบน Community Cloud อย่าแสดงผลสมมติแทนโมเดลในหน้าแอป

## 6. Deploy และติดตาม

ทำตาม DEPLOYMENT_TH ตรวจไฟล์และรุ่น environment deploy บน Streamlit Community Cloud ทดลองลิงก์จริง เก็บ logs หรือบันทึกที่ไม่อ่อนไหวและตรวจดูจริง

สิ่งส่งต่อ: repository/app links, screenshots, monitoring record และเหตุทบทวน ถ้ายังไม่มีคำตอบจริงของ prediction ใหม่ ต้องไม่สรุปความแม่นจริงจาก logs อย่างเดียว

## 7. รายงานและสาธิต

ทุกคนเขียนส่วนงานของตนจากหลักฐาน อ้างอิงข้อมูลและวิธีทำ รวมรายงาน 8–12 หน้าตามเงื่อนไข ตรวจ PDF หลังส่งออก และซ้อมร่วมกันครบ 5 คน

สิ่งส่งต่อ: ชุดไฟล์ ลิงก์ รายงาน PDF contribution/prompt records และการสาธิตที่พร้อมเปิดแอปจริง

## ทางเลือกจัดงาน

แบ่งตามส่วนทำให้เจ้าของชัด แต่ต้องสลับผู้ตรวจเพื่อให้เข้าใจงานรวม ส่วนการจับคู่ช่วยถ่ายทอดความรู้ แต่ต้องนัดเวลาเพิ่ม กลุ่มเลือกวิธีเองและเปลี่ยนได้เมื่อพบภาระไม่สมดุล
