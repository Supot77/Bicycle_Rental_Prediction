# ข้อตกลงข้อมูลก่อนต่อระบบ

ไฟล์ `config/project.json` เป็นที่เก็บชื่อคอลัมน์ที่หลายส่วนใช้ร่วมกัน ค่า null และรายการว่างเป็นสถานะรอ dataset ไม่ใช่สิ่งที่ต้องเดาให้เต็ม

## ช่องที่สมาชิกต้องยืนยัน

| ช่องใน config | ความหมาย |
| --- | --- |
| `dataset.path` | เส้นทาง CSV จากราก repository เช่น `data/raw/ชื่อไฟล์จริง.csv` ใช้ `/` แม้อยู่ Windows |
| `dataset.encoding`, `delimiter` | encoding และตัวคั่นตามไฟล์ที่อ่านจริง |
| `prediction.target` | ชื่อคำตอบที่ต้องทำนายหนึ่งคอลัมน์ |
| `prediction.unit` | หน่วย target พร้อมช่วงเวลา เช่น ครั้งต่อวัน เฉพาะเมื่อยืนยันแล้ว |
| `prediction.context` | ใช้ข้อมูลที่ทราบเมื่อใด เพื่อทำนายอะไร หากทำนายล่วงหน้าให้ระบุระยะล่วงหน้า |
| `prediction.time_column` | ชื่อคอลัมน์เวลา ถ้ามี แยกจากการตัดสินใจว่าจะใช้เป็น feature หรือสร้าง feature เพิ่ม |
| `numeric_features` | รายชื่อข้อมูลเข้าที่กลุ่มตัดสินใจใช้เป็นตัวเลข |
| `categorical_features` | รายชื่อข้อมูลเข้าที่กลุ่มตัดสินใจใช้เป็นหมวดหมู่ |
| `excluded_columns` | คอลัมน์ที่ตัดออก เช่น identifiers หรือข้อมูลเฉลย พร้อมเหตุผลในพจนานุกรม |

คอลัมน์ที่เก็บเป็นตัวเลขอาจหมายถึงหมวดหมู่ เช่น รหัสประเภทวัน จึงไม่จัดชนิดจาก dtype อย่างเดียว และไม่จำเป็นต้องใช้ทุกคอลัมน์

## วิธีเติมโดยไม่เสียต้นฉบับ

1. วางไฟล์ต้นฉบับใน data/raw และอ่าน notebook 01
2. ยืนยันว่าแถวหนึ่งแทนอะไรและมีหลายแถวต่อเวลา/สถานีหรือไม่
3. เขียนพจนานุกรมก่อนเลือก feature ตรวจว่าแต่ละตัวทราบได้ขณะทำนาย
4. เก็บคำถามและข้อยืนยันจากอาจารย์ใน decisions
5. ค่อยแก้ config แล้วรัน `python scripts/check_setup.py --require-data`

ตัวตรวจป้องกัน target อยู่ใน features และคอลัมน์ที่ประกาศหายจากหัวตารางได้ แต่ไม่รู้ว่าคอลัมน์ใดเป็นส่วนประกอบของคำตอบ ข้อมูลหลังเหตุการณ์ หรือใช้หน่วยผิด จึงยังต้องตรวจด้วยคน

## ข้อตกลงก่อนต่อแอป

บันทึกชื่อ/ชนิด/หน่วย/ช่วงค่าที่รับ วิธีแปลงหมวดหมู่ ค่าที่ไม่รู้จัก และวิธีจัดการ input ไม่ครบ รวมถึง output ของ pipeline กับวิธีปัดค่าในหน้าจอ

กลุ่มต้องเลือกวิธีบันทึกโมเดลเอง แต่ pipeline ฝึกและแอปต้องใช้ transformations และ feature order ชุดเดียวกัน ตรวจจาก input เดียวกันอย่างน้อยหลายกรณี โดยเทียบค่าดิบก่อนจัดรูปแบบแสดงผล

ยังไม่มี input controls ทำนายจริงใน app.py เพราะยังไม่รู้ schema สมาชิกจะเขียนส่วนนี้ใน notebook 05 และ app.py หลังผ่านงานโมเดล
